# 业务测试清单与实时观察：需求、实现与验收

## 目标

普通用户操作 Web 或 Android 测试时，不需要理解底层编排。主界面显示实际业务功能及其安全检查、当前实际操作画面、已确认问题和待处理状态。底层模型仍调用原有工具、生成请求变体、积累测试资产并执行原有验证；本次不是移除执行引擎，也不是把它改名后继续显示。

统一体验：选择目标和授权范围 → 形成真实可执行的业务清单 → 执行时更新当前项和画面 → 核对证据 → 已完成项划线 → 确认问题保留 → 本轮结果与报告一致。

## 原界面与目标的差距

基线是 `BolaSecurityTestGate-appium-https-closure.zip`。本次实际检查并修改其源代码。上一版已有业务功能面板，但不是完整的业务 todo 产品体验。

| 原有断点 | 本次实现 | 验收重点 |
|---|---|---|
| 业务界面夹带调用轨迹、内部状态及原始数据 | 独立 version=2 用户视图，页面不再读取原始快照 | 已挂载的三个页面无底层标签或原始输出 |
| 清单/问题被截断，多个端点重复表现为多个功能 | 以业务功能与候选检查组织，不再 slice 截断；提供搜索、筛选和滚动 | 65 项投影与 35 项浏览器场景仍完整 |
| 跳过、失败、单纯任务结束可能被当作完成 | 执行状态与证据结论独立；八种状态 | 跳过、未执行、失败、受阻、待复核不划线 |
| 只取某个任务最后一份结果 | 每任务、每结果来源取最新，所有涉及来源都必须满足完成条件 | 较早未决结果不能被最后一个正常响应掩盖 |
| 仅有抓包完成/设备快照，缺少正在执行的业务项 | App 业务步骤拥有稳定测试标识和持久化进度 | pending→running→completed 在整轮结束前可见 |
| 单次旧截图可能被认成正在实时操作 | Web 只读采样；App 步骤内真实观察；绑定运行、任务及业务项 | 无图不借用上一项画面，过期图不标实时 |
| 页面刷新、切换记录、慢请求可能产生旧状态覆盖 | 先订阅后读取、事件版本、请求取消、连接清理、降级轮询 | 重连、跨记录隔离、卸载后不再更新 |
| App 入口要求用户填写动作 JSON | 普通用户选设备、上传授权 APK、选择已配置业务场景 | 控件定位和 HTTPS 断言留在服务端 |
| 问题页/报告页回到原始内部数据 | 与主界面共用同一用户投影；导出业务 Markdown | 同一轮的覆盖数、确认数、未完成项一致 |
| 构建使用与锁定依赖不匹配的样式插件 | 依照现有 Tailwind 3 依赖改回 PostCSS 配置 | 配置修复已做；完整生产构建仍须实测 |

## 面向用户的状态契约

| 状态 | 是否划线 | 对用户的含义 |
|---|---|---|
| 待测试 | 否 | 已进入本轮计划，尚未执行 |
| 正在测试 | 否 | 执行中，画面及状态可以持续变化 |
| 已完成，未发现确认问题 | 是 | 已完成声明的检查，不代表不存在其他漏洞 |
| 已完成，存在确认问题 | 是 | 检查已结束；红色问题标记与问题详情继续保留 |
| 执行失败 | 否 | 测试未完成，不能当作漏洞或安全结论 |
| 受阻 | 否 | 授权、身份、设备或其他前置条件不满足 |
| 待复核 | 否 | 有结果但未达到充分证据条件 |
| 已跳过/未执行 | 否 | 不计入完成数，不伪装成通过 |

划线表示“这项工作已完成”，不是“应用安全”，也不是从列表删除。业务功能只有其所有检查都完成才划线。进度分母保留本轮所有清单项，不能靠跳过任务让进度变成 100%。运行本身的“本轮已结束”也不等于每一项都完成。业务检查全部完成但收尾失败时，明确提示整轮不能视为通过。

## 确认问题的依据

界面不再仅凭模型输出 `vulnerable` 就确认。已有执行器写出的基准请求、测试变体、原生执行、执行记录、缺失证据与前置条件字段共同参与投影。存在后续前置条件缺口或回放缺口时降为待复核。相同任务、相同来源的更新不重复累计。

本次没有重写所有漏洞判定算法，也没有证明所有模型结论都绝无误报。用户视图依赖执行引擎产生的证据；它不是独立于引擎的第二套漏洞验证器。原始内部接口和资料仍供内部执行或受控运维使用，未被删掉。

App 页面/HTTPS 业务场景完成只算功能检查完成。例如预期的 401 是成功的拒绝访问检查，不会制造漏洞。对跨账号访问等安全问题的确认仍走安全验证器，不因为点击成功、截图成功或抓到包而确认。

## 实时观察不是录像造假

Web 在真实页面存在期间约每秒进行只读截图，单次只允许一个在途采样，遮盖密码、一次性验证码及带 `data-sensitive` 标记的控件。App 在动作后的观察与断言期间发布画面，最多约每 750 毫秒一次；一次性动作仍只发一次，最终观察另外保存。两者都不是视频流或远程人工接管。

服务端保留有界的最新观察槽位和步骤证据，事件仅发送图片地址，不把大幅图片塞入每条事件。图片读取校验运行归属、类型、魔数和大小。界面显示采集时间；停止观察、超过新鲜窗口、断线或运行结束后不再显示为实时。测试不存在页面动作时显示缺少画面的原因，不用其他页面的截图填空。

页面遮盖不等于全量个人信息脱敏。测试需使用隔离账号和数据，截图及证据接口必须处在受控访问范围内。隐藏内部信息是产品呈现边界，不是新增的多租户授权机制；既有服务的身份认证、访问控制和部署隔离仍须负责安全边界。

## 实现路径

- `src/pages/AIScans.tsx`：目标、授权与业务范围入口；实际创建及启动测试，不展示内部 JSON。
- `src/components/assessment/AssessmentWorkspace.tsx`：完整清单、删除线、确认问题、画面关联、跟随当前项、搜索筛选及窄屏布局。
- `src/components/assessment/AssessmentResults.tsx`、`src/lib/business-report.ts`：同源问题与报告。
- `src/lib/assessment-feed.ts`、`src/hooks/useAssessmentFeed.ts`：事件连接、刷新、切换记录和断线降级。
- `server/src/services/ai-scan/product-state-service.ts`：独立业务状态投影，不输出凭证、完整配置、工具输出或截图正文。
- `product-event-hub.ts`、`product-stream.ts` 与仓库变更发布：订阅、状态重同步、背压合并、心跳与清理。
- `browser/live-observer.ts`、`persistent-browser-runtime.ts`：真实 Web 页面只读观察。
- `mobile-lab-service.ts`：真实 App 测试步骤的进度和观察生产，重试先重置状态，失败后未执行项保留。
- `mobile-business-scenarios.ts`：服务端场景、应用绑定、依赖拓扑、授权域名、UI 与 HTTPS 断言校验。
- `mobile-app-service.ts`：服务器保存已验证安装包描述，用户端只引用安装包标识，不提交本地路径。

主要新增/调整用户接口：`GET /api/ai-scans/product-runs`、`GET /api/ai-scans/:id/product-state`、`GET /api/ai-scans/:id/product-events`、`GET /api/ai-scans/:id/frames/:frameId`、`GET /api/mobile/business-profiles`。创建、启动、选择范围及上传使用 `view=product` 返回用户视图；内部调用保留原执行接口。

事件是“最新状态”的可靠重同步，不是持久事件日志回放。数据库是恢复依据：同进程发布即时触发，定时读作为兜底；浏览器重连或刷新会读取当前状态。没有新增分布式移动调度保证，上一版单设备与单后端调度限制仍有效。

## 覆盖边界

Web 清单来自已有发现及测试候选，不预填虚构的登录/找回密码“已测结果”。App 普通入口的场景来自管理员为具体应用配置的实际步骤；模型继续利用这些操作产生的业务流和测试资产执行后续安全检查。没有配置的任意 App，不会凭几个名称自动获得正确控件定位、业务断言和所有功能覆盖。

本次未实现任意 App 的无配置全自主遍历、无遗漏覆盖证明、证书绑定通用绕过、iOS、视频直播或全新多租户权限体系。独立直接调用移动会话测试接口不自动等同于主产品运行；用户主入口使用与扫描运行关联的 Agent 调用路径。

实际回归、未通过的生产检查和环境限制见同目录 `VALIDATION.md`；操作及部署见 `RUNBOOK.md`。目录中的界面截图带有“受控界面验收/非真机”标记，只证明组件渲染和交互。
