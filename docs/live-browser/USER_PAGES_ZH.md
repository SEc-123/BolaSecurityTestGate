# 用户侧页面、入口与排版核对

本清单依据本次修订源码的实际 `src/App.tsx` 路由及其引用组件，不依据旧目录里存在的文件名推断功能。它描述的是已实现界面，不是规划中的完整后台。

## 1. 当前只有三个顶层页面

| 地址 | 导航名称 | 真正挂载的组件 | 用户能做什么 |
|---|---|---|---|
| `/` | 业务测试 | `AIScans` → `AssessmentWorkspace` | 创建 Web/Android 测试、切换测试记录、查看清单/状态/问题、实时观看 Web 浏览器 |
| `/findings` | 发现问题 | `Findings` → `AssessmentResults(mode="issues")` | 切换测试记录、看已确认问题与待复核信号、定位回对应测试 |
| `/reports` | 测试报告 | `AIReports` → `AssessmentResults(mode="report")` | 看本轮业务覆盖/完成情况/已确认问题、导出 Markdown 报告 |

`/?run=...&test=...` 是在业务测试页定位某轮和某项，不是一个第四页面。未识别的路径在当前前端会回到业务测试页，而不是真正 404。

`archive/frontend-internal-pages/` 和源码中未被 App 引用的内部组件不代表用户可从导航打开。普通用户没有 mutation、learning、workflow、Agent 工具日志、数据库表或任务编排编辑页。底层仍有大量 API；不能把“不出现在导航”当作后端权限隔离。

## 2. 全站外壳

桌面采用深色左侧导航 + 白色顶部栏 + 浅灰内容背景 + 白色卡片。

左栏展开宽 264px，折叠宽 64px；三个入口是业务测试、发现问题、测试报告。侧栏开关只影响排版。顶部栏高 64px，左侧显示当前页面及说明，右侧有 EN/中文切换。新增 noVNC 工具条提示目前以中文为主，不等于本次已经补全所有语言翻译。

初次加载宽度达到 1024px 时侧栏默认展开；小屏低于 768px 时自动收起为图标栏。窄屏仍保留 64px 图标栏，不是滑出式遮罩导航，也不是手机原生客户端。

## 3. 业务测试页：用户的主操作面板

页面最大宽度 1680px，居中，内边距 16px/24px。顶部左边是标题和说明，右边是测试记录下拉框、刷新和新建测试按钮。切换记录不会自行重跑。

### 新建测试（当前页内展开的卡片，不是独立页面）

桌面是左右两列，窄屏上下排列。

用户可选择 Web 或 Android App、输入名称、目标地址、自然语言目标、选择检查范围，并确认测试授权。可展开填写两个隔离的测试账号；它们是被测应用的账号，不是 BSTG 平台的登录账号。

检查范围有 13 类：跨账号越权、角色权限、登录与身份验证、验证码校验、业务规则、重复提交、文件上传、文件下载、文件访问范围、页面脚本注入、命令注入、支付密码、业务操作顺序。

Android 额外需要选择有效设备环境、上传 APK、选择与包名绑定的可执行业务场景。前端上传限制为 80 MiB；切换环境会清空已选安装包/场景；App 业务服务要求 HTTPS。无有效设备、安装包或场景时不能假装完成配置。

创建后可在 created / awaiting_selection / failed 状态使用“继续测试”。没有独立的测试暂停/终止按钮。直播中的“暂停观看”不是暂停测试。

### 测试执行区

最上面一张全宽状态卡：当前阶段、已完成/总数、确认问题数、状态连接提示、刷新与进度条。

下面桌面两栏，约左 36% / 右 64%；精确 CSS 为 `minmax(280px,.8fr) minmax(0,1.4fr)`，在 1024px 以下改为上下排列。右栏桌面采用 sticky，随清单滚动仍可旁观。新建卡片展开时位于整个执行区上方，不覆盖直播。

左栏是功能分组 + 业务测试项，支持搜索和全部/发现问题/未完成/已完成筛选。列表最长 720px 后内部滚动。点击某项右侧跟随该项；“跟随当前测试”回到自动跟随。全部已完成才对功能标题划线；失败、受阻、待复核、跳过、未运行不计为完成。

右栏依次是：

1. 当前业务项、执行状态和用户可理解的说明；
2. **Web：真正的 noVNC 实时浏览器面板**，或 Android：原有 Appium 逐帧观察；
3. Web 的可折叠“截图证据”，明确标注静态而非直播；
4. 本轮已确认问题卡片，显示业务名称、严重性、说明和证据数量；
5. 可展开的待复核信号。

Web 直播工具条有状态、同一业务的可选浏览器、重连观看、暂停/恢复观看、全屏。画面是 AI 操作的同一个桌面，不是另开一个 iframe 浏览目标。观看只读，不提供远程手动接管、复制剪贴板或调整被测窗口大小。全屏只改变观看端缩放。

测试完成后，清单项以删除线保留；有问题的项仍保留问题标记和问题卡片。直播结束不会变成视频回放；当前没有录像时间轴或历史录像播放器。

## 4. 发现问题页

最大宽度约 1152px（max-w-6xl），居中单列卡片。顶部是标题、选择测试记录、刷新。

下面依次为测试名称/状态/覆盖摘要、目标地址、确认问题列表、待复核信号。问题卡片包括标题、业务功能、测试项、严重性、证据数量、结论摘要，以及“查看对应测试与实际画面”的链接。

这里不是一个完整工单管理系统：没有分派负责人、工单状态、修复审批、团队评论或任意原始证据文件浏览器。证据数量不等于页面已经展开全部原始 HTTP/DOM/视频内容。

## 5. 测试报告页

同样约 1152px 单列。顶部与问题页相似，多了“导出报告”。报告从同一份业务状态生成，内容包括测试摘要、按业务功能组织的覆盖清单、完成删除线/状态、确认问题、待复核信号。

当前导出是 `.md` Markdown，不是 PDF、Word、Excel 或完整证据归档，也不是视频下载。没有新增虚构的格式入口。

## 6. 当前用户界面还没有的入口

没有 BSTG 原生登录/注册、用户与租户管理、角色权限配置、模型提供商/API Key 设置、测试设备管理、App 场景编辑器、工作流或变异策略编辑器。设备/场景/模型等仍在部署端或管理 API 配置。

这一事实与“底层功能由模型使用、不让普通用户看到”是一致的界面裁剪，但不代表用户鉴权已经完善。远程部署必须保护整个站点和管理 API，而不仅是直播入口。

## 7. 与本次整改直接有关的边界

本次改变 Web 的观看传输、同浏览器操作能力、会话生命周期、鉴权票据及验收；没有把全部原生 HTTP 安全检查改写为 UI 点击。接口测试没有页面动作时明确显示待命或无对应浏览器，不安排动画假装测试。

本次按真实源码列出布局；noVNC 组件在 Chromium 实际渲染并检查了窄屏。但没有完成全部三个页面在生产 React18/完整 Express 环境的浏览器验收，不能把代码核对与受控组件渲染说成整站生产验收。
