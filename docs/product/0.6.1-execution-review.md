# 0.6.1 原生执行链路修正

本轮基于已提交的 0.6.0（`f373787`）继续审查采集之后的执行路径。仍按用户要求只做代码与构建阶段，没有连接真实 Web 目标或 Android 设备验收。

## 定位到的执行问题

1. 原生基线工作流同时加载攻击字典和基线字典，二者修改同一个位置，可能覆盖变体；基线并不一定是捕获到的原始请求。
2. Cookie 登录的实际会话被当成 `auth_token` 使用；工作流仍读取 `order_id/file_id`，与界面提供的 `object_id` 不一致。
3. 替换 Cookie 时可能保留另一个身份的 Authorization；会话罐还可能在替换后再次覆盖身份。这样的组合不能证明跨身份边界。
4. JSON 数字和布尔参数统一被替换为字符串，导致实际服务的类型校验拒绝请求，而非触达被测业务。
5. 原生编排按流程排序选择最后一个接口，与直接验证选择的目标接口可能不同，参数会被绑定到另一个请求。
6. 自动创建环境使用完整入口 URL。模板执行又拼接完整请求路径，输入 `https://host/app` 时会错误请求 `https://host/app/api/...`，入口自带尾斜杠时还可能产生双斜杠。
7. 文件上传先调用不支持二进制 multipart 的通用变异器，正常上传尚未发出就可能失败；表单元数据保存在制品中却未读取，上传请求还丢失登录身份。旧判断把接受扩展名等同于影响。
8. 工作流执行发生错误或生成零个执行组合时，返回值仍可能表示成功；学习修复后证据仍引用最初的失败运行。

## 修正

- 捕获请求的基线使用独立的原样回放合同，校验已观察的响应状态；不载入变体变量，不补造通用跨步骤映射，也不为了增加资产数量生成自映射。
- 变体绑定按具体类别选择一个明确来源：输入攻击值、受测对象标识或真实会话；基线值不再覆盖变体。
- 统一规范化真实 Cookie/Authorization；身份替换同时清除旧 Cookie 和 Authorization，并使用一个完整的会话绑定。会话罐不覆盖显式身份，Cookie 合并按名称去重并保留值中的等号。
- 使用同一个实际 `object_id`；保留 JSON 原类型；显式指定被测接口。原生账户只按本轮扫描标签复用，不按全局同名账户复用。
- 自动新建与重试的环境保存 origin，入口页面 URL 仍用于浏览器导航。
- 失败和零执行不再返回成功；证据门禁检查执行错误；修复后的基线证据引用实际重跑编号。
- 新增会话字段和序列化的会话头在模型上下文/导出中按已知凭据规则清除。

- 文件上传改用专用二进制执行器：读取实际表单/抓包结构，保留隐藏字段、独立会话、multipart 边界和准确字节；持久化请求、响应与哈希。正常文件上传并回访成功后才发送变体，HTML/SVG 要在目标浏览器观察唯一执行标记，PHP 需要服务端输出唯一标记；接受文件或返回成功码不能确认漏洞。
- 结果界面支持专用上传证据合同，不伪造通用模板/工作流运行编号。缺失单文件字段、无法回访、会话或证据不足时明确显示失败或待复核。全部变体被拒绝时再上传正常对照，避免把过期会话或一次性令牌误报为安全。

上传自动验证支持已观察的单文件 multipart 接口；多个文件字段、仅返回不透明文件 ID、内容加工后不能按字节回访、一次性表单令牌和特殊文件业务需要相应适配。测试上传的文件会留在授权目标中，工具不会猜测删除接口。运行说明中的边界仍适用。

这些修改修复的是请求编译、身份传播与结果关联。响应状态相同只证明本轮基线回放条件满足，不能证明业务正确或目标安全；业务漏洞确认仍需要对应对照证据。
