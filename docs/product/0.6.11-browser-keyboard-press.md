# 0.6.11 local browser keyboard candidate

The real Web run supplied to this isolated repair persisted `Cannot read properties of undefined (reading 'press')` for `browser.interact` with `{action:"press", key:"Escape"}`. The invocation omitted a selector and failed as terminal `action_or_after`. Only this filtered diagnostic metadata was supplied. This repair did not inspect the target, saved credentials, prompts or live browser, and did not operate or replay the live run.

The tool schema allowed a selectorless operation, but the runtime type required a selector and the implementation unconditionally called `locator.press`. The locator was initialized only when the input contained a selector. A local Chromium regression reproduced the exact exception against the clean 0.6.10 commit `8835cc53866f6c177e22eb30f34da13d3494ace2`, establishing a code contract failure independently of the model or target application.

## Keyboard contract

For `press`, an omitted selector sends the allowed key once through the persistent page's keyboard to its current focus. It does not choose, focus or click another element. A supplied selector uses the existing live visible locator and must identify exactly one visible match before `locator.press` focuses that control and sends the key. An explicitly invalid, empty or null selector never falls back to page keyboard.

The existing allowlist remains Enter, Tab, Escape, ArrowDown, ArrowUp, ArrowLeft, ArrowRight and Space. Modifiers and other keys are rejected before dispatch, with `pre_action`, `action_performed:false` and `retryable:false`. The tool description, key enum and TypeScript input type now describe the same behavior.

Both keyboard paths retain scope and cancellation checks, context ownership, the existing selector recovery rules and the post-action observation/evidence flow. Immediately before dispatch, cancellation and target scope are checked again. A dispatch or later observation failure is terminal, with no automatic retry or fallback. A failed call that may have sent the key never reports `action_performed:false`. Successful keyboard input is still separate from a verified business outcome.

## Correction budget

Adding a successful page-level press exposes an assumption in the 0.6.10 recovery reset: every successful `press` had previously required a selector. The reset now explicitly requires a nonempty selector. Repeated selectorless Escape calls cannot replenish the two-correction allowance. A successful selected-control press still resolves the correction episode. Existing task/run limits, allowed task types and unchanged-action rejection are retained.

## Verification and delivery limits

The new real Chromium fixtures verify one trusted keydown and one trusted keyup for selectorless Escape and selected-control Escape, including a hidden duplicate. The selected control receives the key even when another input was focused. A separate UI assertion verifies the native dialog's close event; a successful press alone is not counted as that result.

Failure coverage includes missing, hidden, ambiguous and malformed selectors; explicitly invalid supplied selectors; unsupported keys; cancellation before dispatch, while waiting for a selected control and after real dispatch; and target scope rejection. The scheduler receives injected failures after real page/locator keyboard dispatch and terminates without replay. A real Enter form submission that times out during navigation also submits once and terminates. Additional real-browser sequences verify that page press cannot replenish corrections and selected-control press still can.

Exact test counts and commands are in `validation/release-0.6.11.json`. Tests use native SQLite and local Chromium. Model replies are explicit loopback protocol fixtures. Mobile checks use Appium/device doubles. Full AI Web and Android acceptance remain false; no live Web run, actual model, APK or Android runtime was exercised by this repair.

The two additional legacy static UI audits still fail on the same outdated label and page-list expectations. Their failures were independently reproduced from a temporary source archive of clean 0.6.10. They remain separately recorded failures. The aggregate mobile release gate requires actual device execution and is outside this repair's authorization.

The normal local package contains source and frontend/server build outputs, with per-file checksums and a source-tree identity that must match the final commit. Runtime data, saved credentials and captures are excluded. Dependencies are symlinked from the existing local installation; none were installed or downloaded. This candidate is committed locally in its isolated worktree without push, deployment or changes to historical live-run outcomes.
