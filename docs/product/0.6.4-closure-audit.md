# 0.6.4 已保存失败记录的模型拒绝诊断

本版本修正了一个可观察的失败闭环问题：重试记录的 Agent 决策证据保存了模型访问拒绝，但产品快照的数据库查询排除了 `agent_decision`，业务界面因此只显示“服务进程在执行中退出”。产品快照现在会读取此证据类型，并立即把决策压缩为是否属于安全风险/Daybreak 拒绝的布尔分类；原始决策、模型响应、参数和账号不会进入业务投影。仅在持久化的 fallback 决策明确匹配拒绝时展示固定中文说明，普通本地 fallback 不会被误标。

已验证拒绝记录仍为失败，完成数和确认风险数保持 0；说明明确指出分析未完成，结果不能理解为未发现风险。没有重新发送任何上游安全测试请求。本地重启现有 BSTG 服务后，使用已经保存的失败记录复核界面展示。

## 尚未闭环

此前真实 Web 目标的模型调用被上游访问/安全策略拒绝。该拒绝不能靠改写请求、切换模型或本地兜底绕过，所以本版本没有完成真实 AI Web 安全分析；Android 侧也尚未完成真实 AI 安全分析。本版本的 `full_ai_web_acceptance` 与 `full_ai_android_acceptance` 都保持 `false`。早先验证过的 Android APK、Appium、HTTPS 流量与清理是功能链路证据，不是漏洞分析验收。

在相同账号、工作区、模型与 Codex 入口获得适用的访问权限后，仍需使用原保存目标分别完成 Web 与 APK 的模型分析、实际测试动作、证据校验和报告闭环，再更新验收状态。详见机器可读记录 `validation/release-0.6.4.json`。
