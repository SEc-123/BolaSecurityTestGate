## 代码路径

Web：输入 URL → 服务创建并启动持久任务 → Playwright 实际页面/登录/网络发现 → 请求样本存储 → 功能与候选测试建模 → 原生 API/工作流及实际请求变体 → 对照证据判定 → 状态流、报告与证据导出。

Android：上传 APK → SHA-256、aapt、apksigner → 选择实际授权服务 → 固定设备与会话范围 → 安装、代理、证书与 Appium → 自动探索或已配置业务场景 → 按会话、设备、包名、步骤验证抓包 → 录制/API/工作流 → 安全测试 → 清理环境 → 报告。自动探索没有流量时会失败，不能拿截图冒充网络测试完成。

## 覆盖边界

- 自动发现是有界覆盖，不等于遍历所有业务。默认每个 Web 身份最多 12 页、每页最多 4 个导航控件；Android 默认最多 30 步、3 分钟。验证码、跨站 SSO、复杂自定义登录控件需要适配或测试材料。
- 默认主动请求限制在一个 origin。API 与前端跨域时，需要分别明确测试范围，不能从页面引用直接推断获得第三方测试授权。
- APK 中域名只是候选。动态下发或加密隐藏的地址可能无法静态提取；此时要填业务服务地址。APP 的证书锁定、设备不可 root/不信任 CA、硬件依赖和 APK ABI 不匹配会作为实际阻断。
- Android 自动探索主要建立一个页面会话；双账号越权需要两份真实独立会话和对象归属。可提供已登录 Authorization 与标识；不能凭两个用户名就假设两个会话已经建立。
- 反射 GET/HTML XSS 有真实浏览器确认代码；存储型、DOM 型、POST 后页面链路和复杂业务不变量需要对应操作场景。成功状态码或请求差异只能是线索。
- 有损编码的二进制浏览器请求不作为通用文本重放样本；multipart/文件测试使用专门能力。未知结构不会补造输入字段。
- 采集的原始请求/响应和设备证据可能包含敏感数据，保存在本机。下载证据 JSON 会清除已知凭据字段，但不保证业务正文中所有敏感信息都能自动识别。
- 这是单服务本地/专用实验环境工具。代码中的跨进程租约防止同一任务重复启动，不是多租户隔离系统，也不能保证进程崩溃后的未知外部设备状态自动恢复。
