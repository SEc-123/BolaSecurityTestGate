# 0.6.0 安装与操作

## 启动服务

在项目根目录使用与当前平台匹配的 Node.js 环境安装依赖。根目录 postinstall 会安装 `server/` 依赖及本机 SQLite 扩展，不能复用另一台机器的 node_modules。

```sh
npm ci
npm run setup:browser
npm run build
npm start
```

服务按项目配置监听（默认端口 3001），启动后浏览器打开服务日志中的本地地址。`npm start` 同时提供前端与 API。模型服务是可选项；可在“模型设置”添加、修改或停用提供方。未配置模型时使用确定性规划/证据规则，已配置但失败的模型会明确报告错误。

默认 `BSTG_BROWSER_MODE=headless` 使用真实 Chromium 和截图。`headed` 需要桌面环境；`novnc` 需要上游文档中的 Linux Xvfb、VNC、websockify 等完整环境。不要为了默认 URL 测试额外强制启用 noVNC。

## Web

1. 选择 Web，填写完整 HTTP(S) URL，选择检查类别并确认授权。
2. 登录后的功能需要真实测试账号。标准登录表单/SPA 登录控件会尝试使用提供的凭据；遇到验证码、跨站登录或无法验证会话会显示覆盖缺口。
3. 跨账号访问验证可补充用户标识、其拥有的对象标识和已登录 Authorization。标识必须来自实际测试数据。
4. 点击开始。浏览器刷新不会重新创建任务；返回已有记录可以继续观察状态。
5. 在结果中查看风险、待复核项和执行诊断，下载报告或证据 JSON。执行失败时“重新测试”创建新一轮记录，也会重新执行目标操作。

## Android

运行服务的主机需要 Android SDK platform-tools / build-tools、Java、Appium UiAutomator2 与 mitmproxy，另需一个可连接的测试设备。SDK 可通过 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 或标准 Android Studio 目录定位。非标准工具路径使用 `BSTG_MOBILE_ADB_PATH`、`BSTG_MOBILE_AAPT_PATH`、`BSTG_MOBILE_APKSIGNER_PATH`、`BSTG_MITMDUMP_PATH`。

1. 启动设备与 Appium，在“配置 Android 测试设备”填入 `adb devices` 中的序列号和 Appium 地址。默认界面值 `http://127.0.0.1:4723` 只是常用地址，必须有实际服务。
2. 填写设备能访问到的主机代理地址。Android 标准模拟器访问本机通常使用 `10.0.2.2`；真机应填写可达的实验主机地址。代理由本服务管理，端口需空闲。
3. HTTPS 流量需要设备信任本轮代理证书。在可 root 的专用测试模拟器中可明确开启自动安装；普通设备需事先配置对应 CA。证书锁定会阻断抓包，不会偷偷禁用应用 TLS 检查。
4. 上传完整、可启动且签名有效的 APK（最高 256 MiB，不是 AAB/APKS 分包集合）。选择安装包发现的实际业务服务，或手动填写该服务的 HTTP(S) 地址。候选地址可能包含第三方域名，必须核对。
5. 不选回归场景即可走自动探索。已预先配置的业务回归场景可选，场景配置保留在服务端设备 profile 的 `config_json.business_scenarios`，结构参见 `docs/mobile-lab/APPIUM_HTTPS_E2E.md`。
6. 自动探索使用 Appium 操作真实页面、保存截图/UI/流量，跳过已识别的支付、删除、转账等操作；选中的安全测试仍可能修改隔离目标的数据。
7. 只有匹配当前设备、包名、采集会话和步骤的完整业务流量会导入测试引擎。最终报告会保留证书/登录/未触达页面等缺口。纯 HTTP 会明确标为 HTTP，不能作为 HTTPS 解密验收证据。

## 运行失败后的处理

- 找不到浏览器：执行 `npm run setup:browser`；Linux 还需安装 Playwright 所需系统依赖。
- APK 无法识别/签名失败：检查 SDK build-tools、Java 和 APK 完整性；不要绕过校验。
- 无设备或 Appium 连接失败：核对序列号、设备启动状态、UiAutomator2 驱动和 Appium 地址。
- 无业务请求：检查实际服务地址、是否完成登录、页面是否触发功能、代理可达性和证书信任。
- 服务中断：旧记录保留并标识失败；先检查设备及代理恢复情况，再发起新一轮测试。
- 证据不足/待复核：补齐真实会话、对象归属或业务断言；“没有确认漏洞”不等于目标安全。

## 本次版本验证状态

0.6.0 本次按用户要求只做代码和构建阶段，未运行实际 Web/APK 目标验收。实际环境联调时，应分别验证一个已知有问题和一个已修复的授权目标，核对真实请求、差异证据、界面结果、导出报告与清理状态；历史示例报告不替代本版本验证。
