# 0.6.6 local selector-recovery candidate

This candidate repairs discovery-only pre-action selector failures. It is not full Web or Android AI acceptance. No saved external target, APK, saved account, or saved prompt was used or changed by this task.

## Cause and change

The browser waited for the first matching element to be visible before checking uniqueness. A missing or hidden element therefore raised a generic Playwright timeout and terminated discovery before the model received actionable selector feedback.

For `discover_target`, the browser preserves its bounded visibility wait for missing or unique selectors, then classifies `selector_no_match`, `selector_ambiguous`, or `selector_not_visible` before performing an action. Ambiguity includes a selector matching both a visible and a hidden element; no first-match fallback is permitted. Feedback includes the context key, match count, `failure_phase: pre_action`, `action_performed: false`, and at most 20 visible controls with bounded metadata. Input values, sensitive subtrees, raw HTML, full page text, cookies, and URL queries are excluded from this feedback.

The scheduler permits at most two correction decisions per task, shared across these errors, only for `browser.interact` with `discover_target` intent and both pre-action markers. Invalid syntax, actionability timeouts after successful selector validation, failed assertions, post-action exceptions, and scope/auth/provider failures remain terminal. Provider refusal still stops the run. Model projection prioritizes the phase and action markers with the error code; real scheduler tests inspect the next provider request to verify that control evidence survives.

## Validation scope

The Chromium regressions use disposable HTTP target and model-protocol fixtures bound to `127.0.0.1`. Chromium, native SQLite, and the real scheduler execute locally; model decisions and denial responses are explicit fixtures, not real AI acceptance. Tests cover click and fill correction for missing, hidden and ambiguous selectors, bounded failure with zero mutation requests, denial during correction, terminal non-discovery errors, invalid selectors, actionability failures, and failed assertions. A separate projection regression adds bulky browser history and checks retained feedback.

The production product-experience suite, mobile-closure suite, frontend/backend typechecks, and production build are required before packaging. Exact passing counts are recorded in `validation/release-0.6.6.json`. The mobile suite is local regression coverage, not an APK/device run.

Installed dependencies and Chromium were reused without downloads. The local candidate contains source and normal build output, with a checked source checksum inventory. Dependencies, local model/runtime configuration, secrets, runtime data and saved-target evidence are excluded. No push, deployment, real-target retry, or remote CI verification is claimed.
