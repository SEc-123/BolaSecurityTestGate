# 0.6.9 local browser readiness recovery candidate

The saved 0.6.8 Web attempt `8d5e6453-79a3-44de-aea9-8ebf81bbbf8d` ended **failed**, with 18 completed, 7 failed, 7 blocked and 1 pending task. It retained 65 endpoint request artifacts, 20 feature nodes and 8 candidates. Both AI judgments were inconclusive, with no confirmed risks. This repair uses the incident's safe metadata and local fixtures only. It does not replay the saved target or any APK. Full Web and Android AI acceptance remain false.

## First broken contracts

Discovery corrected an earlier selector problem, then stopped when a visible link's `locator.click` timed out after 20 seconds because a full-screen dialog intercepted pointer events. The existing browser adapter only emitted structured no-action feedback for discovery selector visibility failures. Actionability timeouts fell through to a generic terminal result.

The `email_sms_bypass` and `auth_otp` tasks waited for an unobserved `button:has-text("W")` and failed. That selector is syntactically valid, but it did not identify an observed control. The task runtime already allowed bounded correction for generic/upload test tasks; the browser adapter's discovery-only classification prevented those tasks from receiving the same useful feedback.

Finally, `model_features_and_candidates` remained pending after its discovery dependency failed. The run finalizer recognized the deadlock and marked the run failed without closing the pending task. This left task counts and terminal run state inconsistent.

## Browser correction contract

Click now uses Playwright's `trial:true` readiness check before dispatch. A trial timeout returns `selector_actionability_timeout`, `failure_phase:pre_action`, `action_performed:false` and `retryable:true`. No click is dispatched by that trial. The model receives a recovery hint and bounded control metadata, with dialog controls prioritized and pointer reachability recorded. It may choose an observed safe close/cancel control or another reachable control; no forced click, automatic dialog dismissal or guessed control is introduced. Playwright documents the trial option as readiness checking without executing the click: [Locator.click](https://playwright.dev/docs/api/class-locator#locator-click).

Missing, hidden, ambiguous and malformed selectors also return actionable no-action evidence. Invalid selector syntax is checked before waiting; unobserved labels receive bounded visibility waits. Repeating the unchanged rejected action without a successful observation or different action terminates immediately, without another wait. The existing discovery/generic/upload task scope retains a total limit of two model correction decisions, including when failure categories change. Provider refusals, scope errors, cancellation, disabled controls and failed business assertions remain terminal.

The actual click/fill/select/press is a separate boundary. An error after dispatch is `action_or_after` and `retryable:false`; uncertain dispatch does not claim `action_performed:false`. This remains true if a click sends a request successfully and its subsequent navigation times out. Successful dispatch followed by an observation/persistence failure records `action_performed:true`. No automatic replay follows either case.

Recovery observation contains at most 20 controls and no input values, page HTML, full text, URLs, cookies or password/one-time-code/sensitive subtrees. Feedback fields are prioritized during model-context projection, and the original failed invocation remains persisted. A successful observation or interaction clears the unchanged-action guard so the model can make a decision from new state; the task-wide correction budget still bounds failures.

## Dependency and evidence closure

Before each scheduler fetch, ordinary pending tasks with failed or blocked dependencies become `blocked / dependency_failed`, including cascades. Campaign summary tasks retain their existing ability to aggregate failed/blocked children and run after the cascade settles. Terminal missing or cyclic dependency graphs become `blocked / dependency_deadlock`, with completion timestamps and retained dependency diagnostics. Waiting for user selection, explicit run-budget exhaustion and policy cancellation retain their existing behavior. Terminal summaries count the updated task states.

The upload/request capture gates are unchanged. The incident's upload task correctly failed because no complete observed multipart request or file input supplied its contract; the seven `capture_required` tasks correctly blocked without complete business requests. This repair does not infer file fields, manufacture captured requests, promote inconclusive judgments or claim a vulnerability from a recovered click.
